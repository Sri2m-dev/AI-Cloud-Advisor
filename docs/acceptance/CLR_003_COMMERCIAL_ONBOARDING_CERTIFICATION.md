## Commercial Onboarding Model

Nexora supports two governed customer onboarding modes.

### Zero-Access / Evidence Import

Customer-approved evidence -> governed admission -> semantic governance -> normalization -> SourceFacts -> Data Fabric / Registry / Relationships -> Enterprise / Financial / Technology Intelligence -> Ask Nexora.

This mode does not require Nexora access to the customer's cloud account.

### AWS Connected Mode

Customer AWS Account -> customer-created read-only IAM Role -> Nexora AWS Principal -> STS AssumeRole + Nexora-generated External ID -> temporary STS credentials -> controlled discovery and synchronization -> SourceFacts -> Data Fabric / Registry / Relationships -> Enterprise / Financial / Technology Intelligence -> Ask Nexora.

Customer long-lived AWS access keys are not required.

## Architecture Convergence

Both onboarding paths converge into the existing governed SourceFacts and enterprise intelligence architecture.

No separate AWS Data Fabric, evidence Data Fabric, connector intelligence engine or parallel customer intelligence architecture is introduced.

## Security and Governance

- Organization and tenant boundaries remain authoritative.
- Zero-Access prospect evidence remains isolated.
- AWS Connected Mode uses STS temporary credentials.
- External ID is generated by Nexora.
- Customer long-lived AWS access keys are not required.
- Provenance remains attached to governed evidence.
- Unsupported conclusions remain UNKNOWN.

## Commercial Journey

Upload -> Prove -> Connect -> Automate

Customers may begin with Zero-Access Evidence Import and later enable Connected Mode without changing Nexora's canonical intelligence architecture.
